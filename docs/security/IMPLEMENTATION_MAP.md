# Lodestar-z security implementation map

This is the volatile companion to the stable [threat model](../../THREAT_MODEL.md). It records only
implementation facts needed to establish a trust boundary or precondition.

- **Owner:** `@ChainSafe/lodestar`
- **Last reviewed:** 2026-09-16

## Integration status

Production statuses reflect the maintainer-confirmed baseline. Branch networking changes are noted
separately.

| Surface | Lodestar-z status | Lodestar production status |
| --- | --- | --- |
| BLS and pubkey cache | Exported through N-API | Lodestar-ts still uses `@chainsafe/blst` and its TypeScript pubkey cache |
| State transition | Exported as `BeaconStateView.stateTransition` | Integration is in progress |
| Fork choice | Implemented in Zig but not exported through N-API | Lodestar-ts owns production fork choice |
| Networking and P2P validation | Native QUIC, discovery, req/resp and gossipsub exported through `./network` on this branch | Maintainers report an experimental native adapter consuming public peer traffic. This deployment claim is external to this repository; the native listener and hostile input paths can be exercised here. Host validators and import orchestration remain responsible for consensus acceptance. This does not establish adoption in upstream Lodestar releases. |

A report against an unintegrated surface should be classified as security readiness unless another
supported caller supplies a current hostile path.

## Boundary map

| Boundary or invariant | Current implementation evidence |
| --- | --- |
| Protocol selection | [`router.zig`](../../src/network/router.zig) supplies current receive capabilities to each negotiation pump. [`multistream.zig`](../../src/network/wire/multistream.zig) bounds offer lookup to 64 descriptors and proposals to four. Unselected inbound streams borrow no offer list; capability updates apply when the next proposal is parsed. Once accepted, a caller-defined numeric identity stays latched through acknowledgment backpressure and completion delivery, independently of changes to the offer list. The router maps that identity through shared protocol definitions; it does not reparse a selected wire string. Established streams retain their handler; a new stream negotiates independently. Outbound candidates are bounded, ordered copies whose immutable ID bytes must outlive the negotiation. |
| Managed configuration ownership | [`configuration.zig`](../../src/network/configuration.zig) derives request peer capacity from transport limits, gossip capacities from peer policy, startup entropy from the host seed, and router control reservation from req/resp. Independent overrides preserve the selected profile. Raw module options remain explicit. Composition rejects insufficient request capacity and excess peer or dial capacity before native owners allocate. |
| Managed ownership and turns | [`network_core.zig`](../../src/network/network_core.zig) owns Transport, PeerManager and Service as siblings. [`managed.zig`](../../src/network/managed.zig) lends those concrete owners to the same socket-independent turn in production and tests, retaining no pointers or additional queue. Authenticated peer admission precedes gossip admission and one Service pump; control completion and peer reconciliation follow. Graceful close rejects new application work immediately while Service defers stream cleanup to the next safe pump. Shutdown retires protocol streams before Transport teardown. |
| Peer reconciliation work | [`peer_manager.zig`](../../src/network/peer_manager.zig) evaluates dirty inputs and deadlines only through explicit `reconcile(service, now)` calls. Coverage deficits and discovery need describe the same completed evaluation, including its demand and relevant-peer count; const reads do not refresh reputation, mutate peers, publish events or advance time. Dirty inputs retain immediate owner wakeups, and the host-slot process path owns demand expiry. Quiescence and shutdown clear both observations and stop policy evaluation. The retained-catalog deadline is computed once per reconciliation. [`dial_queue.zig`](../../src/network/peers/dial_queue.zig) resolves each candidate once before applying connection, relevance and deferral updates. [`metrics/snapshot.zig`](../../src/network/metrics/snapshot.zig) copies cumulative selection, deadline and lookup work into a fixed eight-operation Prometheus family; scraping does not advance reconciliation, and shutdown preserves the counters. [`managed_test.zig`](../../src/network/managed_test.zig) covers coherent reads after dirty demand and catalog changes, unchanged reputation/events until reconciliation, metadata deadlines, host-slot expiry and closing behavior. |
| Peer control scheduling | [`control.zig`](../../src/network/peers/control.zig) treats a valid Metadata reply as the end of one refresh attempt, even if its sequence is stale. Cached metadata never rolls back. Later Ping evidence may request another refresh. Pending Metadata and Status retain their first due times; the older demand wins, with Metadata winning a tie. Repeated host Status requests cannot postpone existing work. A pending Metadata refresh replaces Ping work because its response also confirms liveness. There is no timer retry to reach a remembered sequence. Outbound control requests share the request client's absolute negotiation, request-transfer and whole-response deadlines; partial bytes and host chunk consumption cannot renew them. Previous-fork request grace has its own explicitly named duration. |
| Protocol completion fairness | [`negotiate.zig`](../../src/network/negotiate.zig) and [`handler.zig`](../../src/network/identify/handler.zig) rotate completion selection through their bounded slot tables. A full output slice retains later completions; low-slot churn cannot indefinitely suppress them. Negotiation leftovers remain borrowed until the next pump, before slot reuse. Inbound negotiations have a per-connection limit (16 by default), and a separate global outbound reserve protects application and gossip dials in addition to the control reserve. Refusals and inbound failures have fixed-label counters. |
| Networking lifecycle test fixtures | [`CI.yml`](../../.github/workflows/CI.yml) runs shared UDP provider tests in the OS matrix, native runtime tests and instrumented binding suites for both presets. [`stock_packages.mjs`](../../test/interop/stock_packages.mjs) supports pinned installed peers or an explicitly selected trusted Lodestar checkout. The installed fixture uses the test-only `@lodestar/reqresp` 1.46.0 dependency's internal response decoder, checked by an import test. The installed Identify fixture directly pins `@libp2p/peer-id` and runs in CI; import smoke tests cover every stock fixture import. Stock request fixtures advertise gossip, consistent Ping/Metadata sequences and eight-byte Goodbye responses so native peer health checks remain meaningful. Fixture response commands validate sizes before changing response state. CI rejects skipped lifecycle cases; only two explicitly named retained public-network sample tests are optional. Instrumented addons remain excluded from release packaging. |
| QUIC execution ownership | [`engine.zig`](../../src/network/quic/engine.zig) owns connections, streams, admission, authentication and protocol timers, consuming bytes and explicit time without socket I/O. [`transport.zig`](../../src/network/transport.zig) owns that engine, sockets, pacing storage, clock sampling, startup and teardown. Its validated send, receive and total-work budgets bound each turn. Physical scheduler indexes stay internal; queued datagrams retain full connection generations, and both pending-queue cleanup and per-connection service reject reused owners. Ready batches have one owner so a failed batch cannot close an unrelated connection. Transport preserves completed events, activity and work when a later local or keylog failure occurs. Nonblocking receives skip deadline scans. Engine memory reports configured flow-control windows; Transport accounts for its actual queue and batch storage. Plain connection counters live beside Engine, while [`metrics/snapshot.zig`](../../src/network/metrics/snapshot.zig) renders their fixed names and labels outside it. |
| QUIC connection admission | [`engine.zig`](../../src/network/quic/engine.zig) routes existing connections before admitting new Initial packets. Admission rejects destination connection IDs shorter than eight bytes, as required by RFC 9000 section 7.2, before drawing a connection ID, claiming a slot, creating native QUIC/TLS state or inserting routes. The route table's nonempty-key invariant therefore has an explicit check at the network boundary. Per-source and aggregate handshake limits apply before allocation. IPv6 source admission groups /64 prefixes. At half the handshake cap, tokenless Initials receive stateless Retry. HMAC-SHA256 tokens bind the full source endpoint, original DCID, Retry SCID, and a monotonic timestamp; only a valid unexpired token bypasses Retry. Transport obtains one fresh 32-byte secret seed from the secure host entropy provider per engine and fails initialization if it cannot. The engine owns `std.Random.DefaultCsprng` and draws connection IDs, a separate 32-byte Retry key, and the route-table hash seed without further host entropy calls. The generator has no retained interface pointer and remains owned by the serialized engine. Initialization erases temporary secret material; teardown erases the generator and Retry key. Duplicate connection IDs retain checked route refusal and slot rollback. This preserves unallocated slots against spoofed Initials, but authenticated peers can still consume their bounded allowance. Exhausted connection generations retire instead of wrapping. The engine owns CID routing and authenticated identity on each live connection slot; the managed Catalog owns peer-identity lookup. Authenticated path changes update Catalog through full-generation connection handles and produce an updated snapshot for published peers. Duplicate, stale and closing-connection observations cannot publish a replacement endpoint. |
| Gossip negotiation retirement | [`peer_session.zig`](../../src/network/gossipsub/peer_session.zig) owns streams and I/O for one authenticated connection. Its outbound union distinguishes an event-requested opening, negotiation, usable delivery, absence and terminal control exhaustion. [`peer_manager.zig`](../../src/network/peer_manager.zig) admits gossip after connection policy accepts the authenticated transport, independently of Status response ordering. Gossip cannot establish managed relevance; accepted Status still controls compatibility and relevant-peer accounting, and host validators still determine message acceptance. [`session_io.zig`](../../src/network/gossipsub/session_io.zig) opens streams on admission or new inbound-stream evidence, with one outbound negotiation per session and bounded openings per pump. Negotiation failure creates no retry timer. An established direct-peer outbound stream that times out schedules one new negotiation after 30 seconds; failure of that attempt requires new inbound-stream evidence before another opening. Removing direct membership cancels the scheduled opening. Retirement cancels negotiation before releasing a session slot. Connection and stream generations reject stale outcomes; session generations protect write completions. Availability transitions invalidate peer selection through a revision, without polling a shadow peer set. Failed gossip relationships are replaced without a reputation penalty; explicit direct connections remain retained. [`turn.zig`](../../src/network/gossipsub/turn.zig) bounds transport calls, decoding, work and event borrows. [`peer_io.zig`](../../src/network/gossipsub/peer_io.zig) retains receive and send deadlines. [`service_test.zig`](../../src/network/gossipsub/service_test.zig) covers rejection, timeout, new inbound evidence, router cancellation and stale outcomes. |
| Dual-stack socket ownership | [`udp/root.zig`](../../src/udp/root.zig) owns at most one socket per configured address family and delegates binding, I/O and cleanup to the same `std.Io` provider. IPv6 options use provider defaults; overlapping wildcard binds may fail. Partial binding rolls back through that provider. Each synchronous transport owns one receive buffer and lends it to the socket call. The returned datagram borrows that buffer until the next receive, without a release operation or generation token. Ready reads alternate families without spawning tasks. Blocking dual-socket reads use two standard-library `Select` tasks, each peeking through a single-socket receive; cancellation joins both tasks before the caller buffer is used. No multi-socket batch state is retained or inspected. [`udp/root_test.zig`](../../src/udp/root_test.zig) covers arrival during wait setup, provider refusal, partial binding and wait startup rollback, timeouts and ready reads without concurrency. QUIC selects the bound local endpoint for the packet family; connection, handshake, peer and discovery capacities remain shared. [`network_config.zig`](../../bindings/napi/network_config.zig) accepts only one or two listeners with distinct families and copies their bytes before owner startup. The shared [`udp/address.zig`](../../src/udp/address.zig) normalizes IPv4-mapped socket observations to IPv4. Listener validation rejects mapped IPv6 declarations before provider binding; local advertisements and multiaddr boundaries reject them too. ENR projections omit mapped `ip6` endpoints while preserving the signed record and ordinary IPv4 fallback. Discovery validates every supported endpoint before rejecting a signed record, so an unusable IPv4 field cannot hide usable IPv6 discovery or bootstrap reachability. ENR updates cannot advertise a protocol family without its listener, including the IPv6 discovery port fallback. Distance-zero FINDNODE responses consider both local advertised discovery endpoints under the requester's relay-scope policy. Identity and Identify report both endpoints. Linux and macOS native owners poll all protocol descriptors together with the existing host wake descriptor. |
| Native networking lifecycle | [`network.js`](../../bindings/src/network.js) wraps one native runtime per instance. `ready` resolves after preparation; application `applyIntent` activates it. The application factory is the only runtime constructor. [`network_owner.zig`](../../bindings/napi/network_owner.zig) owns initialization and physical network execution; [`network_runtime.zig`](../../bindings/napi/network_runtime.zig) owns JavaScript environment lifetime, bridge storage and terminal settlement. The application configuration builder produces an unresolved request over stable owner storage. Preparation obtains one secure policy seed and resolves the final native plan once, including profile defaults, overrides and admission quotas derived from final capacities. Bridge sizing, budget checks, native construction and reported capacities consume that same plan; no placeholder resolution precedes it. Complete `applyIntent` publication activates the prepared configuration. The `closed` promise reports terminal owner shutdown. Peer observations use the lossless peer lane; operational failures use bounded logs and cumulative metrics. |
| Native network metrics | [`metrics/snapshot.zig`](../../src/network/metrics/snapshot.zig) collects bounded, pointer-free snapshots on the network owner, at most once per second. `getMetrics()` copies under the runtime mutex and formats outside it into at most 512 KiB. Client, direction, failure, method and topic labels use fixed vocabularies; fork labels use configured digests. Scraping does not consume events or mutate peer scores. Score evaluation shares policy arithmetic without changing its cache or decay. Score components are summed per peer over a fixed topic-kind vocabulary before population aggregation; per-kind mesh populations deduplicate peers across subnets and forks. Score call, recomputation and cache-delta counters exclude telemetry evaluation and do not compare reused peer identities. Current peer score, age and metadata distributions are rebuilt from bounded native tables; cumulative dial, lookup, QUIC and peer lifecycle outcomes survive slot reuse and close. Goodbye and Status outcomes use fixed reason labels, including one fallback for unknown Goodbye codes. Subnet and sampling-group gauges copy the bounded peer-selection result, counting only retained peers with fresh compatible metadata and available gossip delivery; scraping never advances selection or custody derivation. Latency histograms and transport byte counters use fixed storage; UDP accounting includes partial send successes and excludes truncated receive payloads. Gossip RPC bytes include partial progress, while completed-frame and decoded-item counters avoid retries. Control and data queues return typed completions only after the entire frame is accepted; control completions retain their token and item kind through partial writes and ring reuse. GRAFT admission logs say queued; sent-item counters advance only on full QUIC acceptance, excluding refused or reset frames; IHAVE, IWANT and IDONTWANT counters share existing bounded scans and fixed topic-kind labels. IWANT latency uses monotonic timestamps in the existing bounded, identity-pinned promise table and starts only at the exact connection/token write receipt; local publication and unsent requests do not count as incoming delivery. The fixed collector registry in [`registry.zig`](../../src/network/metrics/registry.zig) keeps all mutable state local to a gather and accepts only compile-time descriptors. It bounds families to 512, validates names, labels and bucket bounds, rejects duplicate families and histogram sample-name collisions, and escapes label values centrally. The owner snapshot separates live data from totals, high-water marks and configured capacity; close retains the latter groups. Client classification uses a bounded snapshot-local table keyed by connection slot and checked generation, never a remote agent string label. |
| Native gossip diagnostics | [`diagnostics.zig`](../../src/network/gossipsub/diagnostics.zig) captures at most eight retained peers and 512 topic definitions per page on the network owner. Two existing snapshot reservations bound concurrent native results and remain reserved through JavaScript copying. Each result owns its identities, addresses, score counters and component weights; it exposes no native pointers and does not mutate score caches. Validated cursors monotonically traverse at most 512 retained slots. Each page has its own observation time and sequence; pages are diagnostic observations, not an atomic multi-page view. Host score and mesh dumps consume at most 64 pages. Peer reputation snapshots expose the native monotonic update time for explicit wall-clock conversion. |
| Native request and command ownership | [`reqresp.zig`](../../src/network/reqresp/reqresp.zig) owns typed inbound request buffers, selects each physical slot once, and exposes independent application/control output capacities through the canonical [`service.zig`](../../src/network/service.zig). [`request_state.zig`](../../src/network/reqresp/request_state.zig) owns each request's identity, partial frame I/O, notifications, terminal outcome and pending stream cleanup. Shared handle, event and failure definitions live in `events.zig` without importing either direction or the aggregate. The accepted terminal transition returns whether the outcome is new; ReqResp records it once using metadata supplied by Client or Server. Client and server retain their directional protocol states and clocks. Every outbound request uses absolute phase deadlines, defaulting to 5 seconds for negotiation, 5 seconds for request transfer and 10 seconds for the complete response including host pauses. Complete inbound request transfer has an absolute deadline anchored to stream acceptance, defaulting to 10 seconds; partial input cannot renew it before admission. Each inbound response chunk has an absolute write deadline, with separate host and quota durations. ReqResp records timeout accounting at the guarded terminal transition, including negotiation failures. Terminal completion counts malformed request rejections once and records bounded parser details; transmitted error responses have a separate counter and log outcome while preserving the served event as transmission completion and incoming-error counters as native failures. Error responses accept only codes 1–3 and 128–255 through one shared predicate; native and JavaScript boundaries reject reserved codes before changing serving state. Pending chunks precede terminal delivery, borrowed response bytes survive cancellation until consume or terminal delivery, and reported slots recycle on the next pump. Stream cleanup distinguishes router ownership from protocol ownership and retires that owner before recycling. Request policy and identity admission limits form one configuration; their resolved runtime state has one owner. Response pacing remains distinct from identity-based admission. [`network_budget.zig`](../../bindings/napi/network_budget.zig) supplies the mandatory aggregate host payload budget shared by requests, incoming serving and gossip. Incoming JavaScript tokens contain only runtime session, slot index and generation; native request and connection identities stay in the pinned native cell. Incoming `closed` is a void completion after native retirement. [`network_commands.zig`](../../bindings/napi/network_commands.zig) co-locates each command's discriminator, input, result and deferred completion with its generation-tagged lifecycle. Preparing and copying pins prevent release across reentrant JavaScript calls; environment teardown still joins the owner before freeing those cells. The close promise settles only after the joined owner’s eligible final command, request and incoming completions are drained, including copy-failure retirement. |
| Native Status-only updates | [`network.zig`](../../bindings/napi/network.zig) parses and copies complete Status values into the existing bounded command table. `updateStatus` requires an active runtime and executes in the same owner order as complete intents. [`network_core.zig`](../../src/network/network_core.zig) validates against the current fork before publishing Status and invalidating peer selection. Rejected candidates do not change local state. Status-only updates preserve subscriptions, Metadata, ENR sequence, demand and expiry; they neither activate a prepared runtime nor advance the native clock. The host adapter refreshes slot/fork state through a full intent and commits desired Status only after native acknowledgement. Head-slot regression does not imply clock regression. |
| Native identity snapshots | [`network_owner.zig`](../../bindings/napi/network_owner.zig) copies local metadata and the signed ENR on the owner thread into each identity result. Later intent updates cannot alter that result. |
| Native network logging | [`logging.zig`](../../src/network/logging.zig) hooks scoped `std.log` through a thread-local runtime sink, restored before runtime release. Each sink has an independent mutex and a fixed 128-record queue with 768-byte sanitized messages, severity reserves and per-scope/level rate limits. No logging callback enters JavaScript or retains network input pointers. [`network_logs.zig`](../../bindings/napi/network_logs.zig) validates level and batch size, copies at most 32 records and commits only after all N-API allocations succeed. The shared [`network_js.zig`](../../bindings/napi/network_js.zig) projection defines own data properties for objects and array elements, preventing inherited setters from reentering a borrowed drain. Draining is confined to the owning JavaScript environment and remains available after close. Public peer and correlation identifiers are logged; payloads, private keys, JWTs and raw ENRs are excluded. Loss counters are included in metrics. |
| Native network dependencies and validation | [`build.zig.zon`](../../build.zig.zon) pins quiche-zig and Snappy. Native QUIC authentication, framing, req/resp decoding and gossip admission consume hostile network bytes. Req/resp validates every Snappy stream identifier, including repeated and fragmented identifiers; only reserved skippable frame types may carry arbitrary bytes. The standalone request probe checks remote epoch-to-slot multiplication before changing its stored Status or default request slot. QUIC configuration rejects receive budgets smaller than the connection capacity times the 1 MiB minimum connection window; accepted configurations never silently expand the aggregate window budget. Host consensus validators still decide gossip acceptance. Local Lodestar integration bounds host serving and gossip retention across cancelled instances; uint64 peer Status fields require per-peer range checks before conversion to its number-based API. |
| TLS handshake state | [`context.zig`](../../src/network/tls/context.zig) uses BoringSSL’s reserved SSL application-data slot (index zero). Quiche uses separately allocated extension indexes; each object has independent state without addon-global index allocation. Each SSL object retains its own caller-owned handshake state for verification and bounded key logging. Certificates have a 100-year transport lifetime; identity verification still binds the certificate key to the host identity, checks validity, and rejects unsupported key encodings. New key-log files use owner-only permissions. |
| QUIC request half-close | [`client.zig`](../../src/network/reqresp/client.zig) treats peer STOP_SENDING as termination of request transmission only. It releases the request writer and retains bounded response decoding, chunk limits, response deadlines, cancellation, and stream cleanup. A stopped request direction does not authenticate response contents or relax host validation. Other transport failures and response resets remain failures. [`reqresp_half_close_test.zig`](../../src/network/reqresp/reqresp_half_close_test.zig) covers early and delayed responses, buffered FIN, malformed data, resets, timeouts and slot reuse. |
| Goodbye delivery | [`server.zig`](../../src/network/reqresp/server.zig) dispatches a fully decoded, eight-byte Goodbye before stream FIN so a subsequent connection close does not conceal its reason. Framing, size, admission and authenticated connection ownership checks still apply; trailing bytes in the same read are rejected. Other request methods still require FIN. The action closes only the sending peer and sets its bounded retry cooldown. Unknown wire codes share one metric label. |
| Buffered connection teardown | [`peer_manager.zig`](../../src/network/peer_manager.zig) asks req/resp to consume a retained Goodbye before cancelling a closed connection's handlers. The engine retains authenticated identity and read buffers until its next cleanup turn, and full-generation connection and stream checks still apply. The normal decoder and admission checks run before exposing the reason. No buffer survives the existing teardown lifetime, and a selected local disconnect reason retains precedence. A remote STOP_SENDING during response FIN completes serving only after at least one complete chunk and with no pending response bytes; earlier stops remain failures. |
| Discovery candidate selection | [`Lookup.zig`](../../src/discv5/Lookup.zig) optionally borrows a stable caller-owned filter context. [`discovery.zig`](../../src/network/peers/discovery.zig) cancels a foreground lookup before changing its fork context and limits each walk to 128 queries with three in flight. Canonically verified, distance-checked and deduplicated ENRs from authenticated NODES responses may become dial candidates before the advertised node answers discovery. Each response carries at most 16 records; publication copies into bounded output and retains fork, demand, address-family, unprivileged-port and relay-scope checks against the authenticated source. Referrals do not confirm routing-table liveness. Direct authentication refreshes resident and pending routing destinations independently of ENR sequence when the endpoint belongs to the retained highest-sequence record. Subnet quota checks precede mutation; older records cannot restore withdrawn endpoints. The existing dial queue preserves capacity, retry history and concurrency limits, and QUIC verifies the expected peer identity before admission. Direct responder publication remains independent of routing-table capacity. Candidates carry the canonical signed-content hash before source-specific endpoint filtering. Equal-sequence observations must agree on that signed content, while their already-authorized endpoints merge within the two-family bound without resetting active attempts, retry history or host-owned addresses. |
| Discovery I/O isolation | [`Maintenance.zig`](../../src/discv5/Maintenance.zig) owns bootstrap, refresh and routing-replacement probes through ordinary call handles. [`Transport.zig`](../../src/discv5/Transport.zig) owns the Engine, shared UDP sockets and bounded packet workspaces and returns events and expiries; it has no second probe scheduler. `lookup_io.zig` shares concrete lookup and maintenance send/rollback mechanics between managed discovery and the crawler. An unsent probe is cancelled immediately, retains the authenticated incumbent, and waits for the controller retry interval. After two local retry failures, replacement revalidation abandons its pending candidate so another bucket can progress. The default probe interval is one second. A locally refused destination cannot starve unrelated replies or spin immediately. Packet decoding and decryption borrow caller-exclusive scratch; any attempt may overwrite it, including rejection. Protocol state still commits only after validation. The canonical QUIC transport step likewise returns completed progress alongside a possible later failure. |
| Dial intent lifetime | [`dial_queue.zig`](../../src/network/peers/dial_queue.zig) bounds manual connection intent by its host deadline and retires it on success, expiry or cancellation. Generation checks reject stale attempt completions. Direct membership remains persistent; short-lived and unhealthy connections retain escalating retry backoff. Explicit disconnect cancels owned attempts and rejects waiting host promises. |
| Discovery TALK handling | The raw [`Transport.zig`](../../src/discv5/Transport.zig) exposes authenticated TALK requests to its host. Managed [`Discovery.step`](../../src/network/peers/discovery.zig) answers unsupported protocols once with an empty TALKRESP. Send failures remain observable alongside any expiry or candidate progress from that step. Hosts driving the borrowed Transport and calling `consume` own their TALK responses. |
| Discovery socket reachability | IPv4-bound native discovery skips IPv6 lookup and bootstrap destinations. Authenticated QUIC advertisements are filtered against the configured transport family before entering the dial queue, preserving existing fork and relay-scope checks. |
| Gossip resource layout | [`layout.zig`](../../src/network/gossipsub/layout.zig) derives payload entries and pages, shared delivery descriptors, validation capacity, owner-local receive slots, session buffers and retained-table memory from validated startup options. Each owner reports its backing allocations; the aggregate counts separately allocated owner objects explicitly. Each constructor derives its layout from validated options instead of accepting an independently supplied plan. Construction stores its predicted memory plan; allocation-accounting tests reconcile requested bytes, including namespace storage. Per-peer payload-byte limits count logical delivery obligations and do not multiply physical payload storage. Runtime pool occupancy, unused protected descriptors and shared-pool refusals use fixed metrics. [`resource_test.zig`](../../src/network/gossipsub/resource_test.zig) accepts validation with a full delivery pool and allocation disabled, verifies refusal rollback and rejects stale session cancellation. The production-deadline simulation checks descriptor conservation after every service turn; the lifecycle fuzz harness exercises the real delivery pool, partial sends, reservation rollback and teardown. |
| Gossip send pressure | [`outbox.zig`](../../src/network/gossipsub/outbox.zig) owns bounded encoded control queues, live subscription announcements and one delivery queue per session. The default critical queue accommodates a full 512-topic subscription snapshot plus a full PRUNE burst, independently of ordinary control and data capacity. PRUNE queue exhaustion ends gossip eligibility and schedules owner-thread stream retirement; there is no deferred PRUNE table, retry deadline or topic pin. Subscription snapshots begin only when an outbound stream is ready; live changes retain their first pressure deadline and pin topic rows until encoding or retirement. [`delivery.zig`](../../src/network/gossipsub/delivery.zig) bounds shared transmit descriptors with 64 protected descriptors per session and a 512-descriptor ceiling. Each delivery owns one payload retain; immutable payloads own wire framing and topic bytes, while descriptors own only progress, linkage and handles. Session-generation-checked cancellation releases queued payloads, unsent recovery requests and subscription intent together. Sent IWANT promises retain identity pins and receipt-token history across stream loss; late receipts cannot start a cancelled request. Inbound and outbound streams retain independent lifetimes. A live outbound channel owns its stream and negotiated version together; an admitted peer has no invented negotiated version, and the inbound stream stores no unused version. New outbound streams announce current subscriptions. Outgoing GRAFT first admits that topic's pending SUB; only successful GRAFT queue admission creates local mesh membership. Queue residence and progress deadlines, partial-frame boundaries and control/data fairness remain enforced. Fixed-label refusal counters survive slot reuse; logs identify control exhaustion and distinguish receive, subscription and send timeouts. |
| Gossip topic transactions | [`overlay.zig`](../../src/network/gossipsub/overlay.zig) owns the configured namespace, remote subscription bitmap, 512 active rows, mesh and fanout memberships and topic generations. Per-session outboxes own live announcement pins; encoded control frames own their topic bytes. SUB/UNSUB alone owns declared subscription. Accepted incoming GRAFT changes mesh membership without manufacturing a declaration, and established mesh eligibility does not depend on that declaration. Remote unsubscribe and disconnect update membership and scoring in the same serialized transition. Preparation copies namespace ordinals and score parameters into bounded workspace, reserves every destination and leaves protocol state unchanged on refusal. Commit consumes these assignments directly in the same serialized owner call. Validation attribution, unsent announcements, mesh actions, retained scores and backoffs prevent premature row reuse. |
| Gossip message lifetimes | [`messages.zig`](../../src/network/gossipsub/messages.zig) owns the shared compressed store, history, seen IDs and validation lifecycle. Admission reserves an operation slot and an attribution slot before payload acquisition. A scoped reservation commits or cancels in the same serialized owner call, without intervening validation mutation; cancellation preserves prior outcomes and identity attribution. A pending validation slot owns a payload retain and a private attribution-record index; resolved and expired slots retain only their generation and outcome deadline. A separate startup-allocated attribution cache, bounded to four times validation capacity, retains source and duplicate attribution across slot reuse. A startup-allocated ID index borrows stable attribution keys and shares the history/seen cache implementation. The message indexes use independent hashes keyed from the owner’s startup entropy. A single source may hold at most half the validation slots, capped at 128 (with one slot for the smallest configuration). Lookup uses an insertion displacement bound; replacement and expiry remove membership before overwriting keys, while reservation cancellation leaves membership intact. Pending records cannot be evicted; resolved-record replacement and expiry release all identity pins, and unexpired replacements are counted. Each record carries a typed topic generation, and topic retirement observes its pin until attribution expires. Reports return copied topic, identity, timing and ID context alongside any history-owned forwarding handle. An admitted validation can accept, reject, expire or cancel without further allocation; individual forwarding refusals do not undo host acceptance. Payload and validation pools report released capacity to the owner, including validation completion while history or transmit references still retain its pages. Network-owner teardown releases transmit and validation ownership before freeing storage. Validation destruction releases pending payloads and all attribution pins itself; receive and delivery pool destruction requires returned receive slots and descriptors. Receive slots are private u8 indices tracked by a fixed 16-bit occupancy set; they never cross the synchronous Sessions/PeerIo ownership boundary. One optional active RPC owns parser cursors, deferred items, per-frame limits and control observation. Frame completion or discard clears that entire borrow before returning receive storage; a new session cannot inherit an active RPC. History metadata and its payload store are destroyed together after external retains are released. Native-to-host event copies and their independent host byte budget remain required. |

## Host integration contracts

These are Lodestar-ts preconditions supplied by maintainers. They are recorded here because they
change reachability and classification, but they are not enforced by this repository.

- Lodestar-ts owns initial checkpoint decoding and root authentication. Without a user-provided
  checkpoint root, trust is delegated to the checkpoint provider.
- Lodestar loads one version of `@chainsafe/lodestar-z` per Node.js process. Passing zapi class
  instances between different addon versions is unsupported.
- Gossip objects receive their specification-defined validation. Range sync and unknown-parent
  recovery instead establish a parent-root hash chain before processing blocks forward.
- A full state transition is required before a block enters the live chain or fork choice. Archive
  backfill is separate and may persist hash-chain and signature-checked blocks without establishing
  trusted state.
- Signature, transition, execution, and data-availability work may run concurrently, but required
  results join before live-chain and fork-choice admission.
- Execution `syncing` is conditionally valid. Lodestar suppresses validator duties while optimistic,
  and a later invalid result removes the affected fork-choice branch.
- Data availability is required inside its validation window and treated as satisfied outside it.

If code or a supported integration conflicts with any item above, use the code to assess the finding
and update this map.
